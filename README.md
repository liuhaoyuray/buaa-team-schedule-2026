# 北航志工部、实践部课表查询

按日期和时段查询空闲人员、课程安排和联系方式，包含一周总览、共同排期、个人课表、人员名录、工作名单及两校区值班草案。

访问地址：https://liuhaoyuray.github.io/buaa-team-schedule-2026/

## 使用

- **值班表**：分别生成学院路线下、沙河线上值班草案，按周一至周五的 1–2、3–5、6–7、8–10 节排布。每个固定班次会检查有效期内的每一次日期。
- **Excel 导出**：在“值班表”点击“导出 Excel（两部门）”，得到志工部、实践部两个工作表。每张表合并学院路和沙河，值班格内线上姓名后标“（线上）”。现直接采用上传的“26秋值班表.xlsx”两张表的格式，保留14行结构、原字体、边框、合并、行高列宽、部门信息和六行电话区。实际缺口在页面保留。
- **值班核对**：可核对校区、年级和本次参与人员，查看候选人的冲突日期、每人班次数与未排原因；支持复制、打印和导出两校区 CSV。核对设置仅保存在当前浏览器，可导出备份。
- **共同排期**：选择多位同学、教学周和所需时长，查找共同空闲时间；也可按可参加人数推荐时段。
- **工作名单**：在查询结果中勾选人员，复制联系方式或导出 CSV。更换时段后会重新计算名单中每人的状态。
- **显示模式**：右上角可在玻璃效果和清晰模式之间切换；使用深蓝、青绿、冰白配色。
- 工作名单与显示偏好保存在当前浏览器；缺失课表和不明确的安排仍显示待确认。

## 发布

仓库 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。
之后在 Actions 中运行“同步课表并发布网页”，或等待下一次推送。
成功发布后，以 Actions 的 deployment 链接为准。

## 自动更新

- 每次推送到 main 时运行；每小时第 17 分钟检查一次源平台，也可从 Actions 手动运行。
- 源平台有变化时，将页面、程序与整理后的课表数据保存进本仓库，然后发布 GitHub Pages；没有变化时不创建重复提交。
- GitHub 的定时任务可能延迟，自动同步通常不是即时的。
- 数据源：https://buaa-team-schedule-2026.liuhaoyuray.chatgpt.site/
- F 盘新文件仍需先整理并发布到源平台。云端任务不能直接读取本机 F 盘。

`public/` 为同步生成的网页；`scripts/` 和 `.github/workflows/` 为同步、发布配置。
课表下载链接及当前有效人员名单的 CSV 链接指向源平台，不将原始任职表另外提交进仓库。
同步过程不修改此 README 或其他人工维护文件。

## 志愿时长导入（2026-10-27）

从工作台首页或侧栏进入“志愿时长导入”，上传多份系统模板及人员时长清单（`.xlsx`）。文件只在浏览器内处理，不上传服务器；关闭或刷新后不保留，下载不代表已录入系统。

志愿时长入口集成在工作台内，可通过首页、侧栏、手机导航或全局搜索打开；切换到其他功能后返回时，当前页面中的资料仍在。原 `hours.html` 链接自动进入工作台的志愿时长页面。

1. 核对工作表、表头行、姓名与时长列；可提供学号、身份证号、联系方式和清单中的志愿者编号，原始列会保留在核对表中。
2. 按上传的模板顺序处理，可上下调整、修改模板编号；日期支持全局正序、倒序以及每个模板单独指定。例如第四组可设为 `2026-10-23,2026-10-22,2026-10-21`。每人每天最多8小时，不够分配的剩余时长列入待处理。
3. 按姓名匹配，导入编号采用模板原值；重名需要唯一一致的身份资料或手动确认，不按排列顺序猜测。相同身份、相同时长的重复登记计一次；冲突记录需核对原清单。同一系统编号出现在多个模板时，优先使用排序靠前的模板。
4. 二次补录可上传以前成功导入的文件，避开同一编号已用的日期。未上传历史文件时，须自行选择未用日期；程序不能读取志愿系统的实际历史。
5. 下载ZIP：按“先模板、后日期”编号的导入Excel、共用PNG佐证汇总、未匹配及待处理明细、全部人员时长核对、导入顺序说明全部放在同一个文件夹内。可用已有图片代替自动汇总图；汇总图如实呈现上传资料统计。

当前支持 `.xlsx`；旧版 `.xls` 请先另存为 `.xlsx`。时长支持 `10`、`2.5`、`10h`、`10小时` 等值；`100cc` 等不能自动换算，须在结果中手动补正。超长编号使用文本保存，无法保证精度的模板数值编号会中止处理。修改重名编号或时长后须重新核对才可下载。

`features/hours/` 是功能源文件，`scripts/hours-upgrade.mjs` 在每次源课表同步后接入，并复制到 `public/`，源课表无变化时同样保留。ExcelJS 4.4.0 与 JSZip 3.10.1 的浏览器资源固定版本、本地提供，并附许可证；`node scripts/vendor-hours.mjs` 按npm包的SHA-512验证后恢复依赖。

检查：`node --test tests/*.test.mjs`，覆盖姓名/编号匹配、重名、去重、时长拆分、正倒序、历史日期避重、剩余时长，以及Excel导出后编号、格式和总时长的复核。测试资料均为虚构，不提交上传人员资料。

## 报销材料直接生成（2026-10-27）

首页和导航栏的报销入口改为同域名 `reimbursement.html`，不再嵌入旧报销站或调用 `chatgpt.site`。按使用者本次选择，先专注材料生成：无需新建台账、保存云端、办理状态或逐项切换步骤；旧云端台账及历史附件未修改。

上传同一事项、同一类别的发票PDF或照片后，浏览器尝试读取日期、票号、价税合计及费用类别。PDF优先提取文字，扫描件与照片使用本机OCR；无法可靠识别的值留空，OFD保留原件并手工填值。逐张金额相加，按文件摘要及识别出的相同票号阻止本次重复计入；无法替代正式验票。识别结果须人工核对。

选择类别，填写事由、经办人、学工号、部门、经费号和该类别需要的信息与附件，然后直接下载ZIP。经办信息可选择仅在本机记住；发票、原件、事项及生成文件不上传、不保存在云端。

- 每笔生成按原模板填写的内部报销凭单和情况说明，并保留原始附件及本次填写记录。
- 交通、快递需行程单及起止信息，另提供待手写说明文字。
- 物资情况说明嵌入订单截图；加班餐另嵌入小票照片，并自动填写原Excel加班餐审批表。人数按金额÷40向上取整，签字盖章留空按实际办理。
- 劳务不默认要求发票；其他费用须确认实际材料要求。必需信息、附件或逐张金额未齐，不生成看似齐备的材料包。

程序及PDF/OCR资源全部同域名提供，PDF.js 5.6.205、Tesseract.js及核心7.0.0、中文模型1.0.0附版本、来源、许可证及SHA-256记录。`scripts/vendor-reimbursement.mjs` 可恢复资源，`CODEX_CORE_PATH` 可指定已有官方核心目录。正式页面使用同源内容安全策略，不把发票发往远程识别接口。

材料中的人员填写为领款人（报销款接收人），不将其自动填入原模板的经手人或审批表联系人栏。费用发生日期与材料落款日期分开填写：加班餐的用餐日期用于说明正文和审批表，用餐以外的类别使用费用发生日期；落款日期默认当前日期，可修改，用于凭单及说明落款。识别出的发票开票日期仅供参考，不自动当作费用发生日期。订单截图和小票照片嵌在情况说明正文后、落款前。

`features/reimbursement/` 保存源代码与已去除旧个案信息的Word模板；Excel原模板中的示例联系人和年份在生成时替换。每次课表同步均重新接入报销功能。回归检查涵盖总额解析、金额精度、人数计算、材料条件、模板字段、附图和审批单；浏览器端另核验PDF与照片识别、ZIP下载、手机布局及零外部请求。上传的真实票据、个人配置和测试生成包均不提交仓库。
